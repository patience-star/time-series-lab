教科书里的数据是干净的，业务库里拉出来的不是。某天整行没有、同一天报了两次、刷单造成的尖峰、缺货把销量压成 0、指标口径中途改了……这些问题对预测精度的影响，往往比换一个更高级的模型大得多。这一章逐类讲清楚：它们从哪来、长什么样、不处理会怎样、该怎么治。

🧪 脏数据诊所：注入问题 → 自动体检

灰色虚线是真值，蓝线是"拿到手的数据"。逐个勾选问题类型，看图上发生了什么、体检报告能不能抓到。注意三件事：① 缺货只看销量几乎无法确认，必须有库存数据；② "疑似异常点"里总有一批是促销和节假日——那是事件，不是异常；③ 口径突变一旦发生，后面所有的点都"低一截"，但每个点单独看都不异常。

第一步永远是：对齐时间轴

数据库里的明细表是"有事才记一行"，时间序列模型却默认"每个时间点恰好一个值"。所以第一步不是填充也不是去异常，而是把原始记录变成规整的序列：每个日期恰好一行，没有记录的日期明确标成空。

⚠️ 三种"没有"要分清
  • 行不存在：如果业务上"没记录 = 没发生"（比如某 SKU 当天没卖出），应补 0；如果是采集失败，应补 NaN。
  • 值为 NaN：不知道是多少。绝不能直接当 0。
  • 值为 0：真的是零。但要追问一句——是没需求，还是没货/没营业？

重复行怎么合并没有标准答案，要问业务：重复上报 → 保留一条；追加的修正记录 → 保留最后一条；分批到达的流水 → 求和。选错规则，3 月 2 日的值可以是 120、125 或 245。

缺失值：怎么填

时间轴对齐之后，序列里会有一些 NaN。大多数模型不接受缺失，需要填充。填充方法的好坏取决于缺了多长和数据有没有季节：

🧪 实验：五种填充方法对比（和真值比谁更准）

连续缺 9 天时：前向填充是一条平线、线性插值是一条斜线，都丢掉了周内节奏；季节填充（局部水平 × 该星期几的季节指数）把形状补了回来。"当 0 处理"的误差是其他方法的十倍以上——这是实际项目里最常见、代价最大的错误（fillna(0) 或 SUM 时 NULL 被忽略）。

情况推荐做法
零星缺 1–2 个点，季节不强线性插值
有明显季节，缺口短于 2–3 个周期季节填充（同相位估计），或 STL 分解后在趋势上插值再加回季节
缺口很长（数周以上）不要硬填。把序列在缺口处截断只用后半段，或用另一条相关序列回归估计
实时场景只能用过去的信息：前向填充或"上周同一天"，不能用插值（插值用到了未来）
任何情况保留一列 was_missing 标记，让下游知道这个值是估计的

异常值：先检测，再问"是异常还是事件"

异常检测的思路都是同一句话：先估计"正常情况下应该是多少"，再看实际值偏离了多远。方法之间的区别只在于"正常"怎么估计、"多远"怎么度量：

方法"正常"的估计"多远"的度量问题
全局 3σ全体均值全体标准差 $\sigma$没考虑趋势和季节；$\sigma$ 本身被异常值撑大
箱线图 IQR四分位数 $Q_1, Q_3$$\text{IQR}=Q_3-Q_1$比 3σ 稳健，但同样没考虑趋势和季节
Hampel 滤波滚动窗口的中位数滚动 MAD（绝对偏差的中位数）跟得上趋势；窗口内若有季节，带子会偏宽
残差法趋势 + 季节（稳健分解）残差的 MAD最贴合时序特点；实际项目首选

为什么用中位数和 MAD 而不用均值和标准差？因为均值和标准差会被异常值本身拉偏——用被污染的尺子去量污染，量不准。$1.4826 \times \text{MAD}$ 在正态分布下约等于标准差，可以直接替换。

🧪 实验：异常检测器

数据里注入了 6 个刷单尖峰（比正常多 45%–80%）和 4 个故障造成的下跌（只剩正常的 40%–60%）。它们单看数值并不出格——周末和促销日本来就这么高。先用"全局 3σ"：抓到的主要是 618 和双 11，注入的异常大多漏掉。换"残差法"：注入的异常基本全中，但大促和小促也被标了出来。把阈值调高可以少报一些事件，但也会开始漏真异常——光靠调阈值分不开它们，必须引入业务日历。

💼 异常 vs 事件：处理方式完全相反
异常（刷单、故障、测试数据）事件（大促、节假日、发版）
会再次发生吗不会，或不可预知会，而且日期已知
怎么处理置空 → 填充（或缩尾到判定带边界）保留原值，加事件特征（是否大促、距离春节几天）
误处理的后果留着 → 预测偏高、季节系数失真删掉 → 模型永远预测不出大促，备货严重不足

实操做法：维护一张业务日历表（促销排期、节假日、发版、已知故障），检测到的异常点先和日历对一遍，对得上的是事件，对不上的才进入清洗。

缺货截断：销量 ≠ 需求

我们想预测的是需求，但数据库里记录的是销量。只要有货，两者相等；一旦缺货，销量被库存上限"截断"，记录下来的数字低于真实需求。这在统计上叫删失数据（censored data）。

可怕的是它会自我强化：缺货 → 销量低 → 模型以为需求低 → 订得更少 → 更容易缺货。

🧪 实验：缺货如何带偏预测

阴影区是缺货期。把"缺货结束距今"调到 0–3 天：用原始销量训练的预测（橙色）明显低于真实需求；还原后（粉色）回到正常水平。再把它调到 14 天：模型已经开始"忘记"那段缺货，影响变小——离现在越近的脏数据，危害越大。

💡 怎么识别和还原
  • 识别：最可靠的是库存快照（期末库存 = 0）或上下架状态；没有的话，用"销量骤降到接近 0 且前后正常、同期其他门店/SKU 正常"作为线索。
  • 还原：把缺货日当作缺失，用季节填充或模型预测值替代；且还原值不应低于实际销量。
  • 部分缺货（下午才卖完）更隐蔽：有小时级数据时，可用当天缺货前的销售速度外推全天。
  • 同理，限购、限流、闭店也会造成截断，处理方式相同。

口径突变：新老数据不可比

某一天起，指标的统计方式变了：日活从"启动 App"改成"停留超过 10 秒"；销售额从含税改成不含税；某个渠道的数据被剥离出去。曲线会出现一个台阶——每个点单独看都不异常，但前后两段不是一个东西。

🧪 实验：检测并对齐口径突变
日活数据（某天起去重规则变严，数值下降）
突变扫描曲线：每个位置"右侧 8 周中位数 − 左侧 8 周中位数"，以稳健标准差为单位

扫描曲线在口径变更处形成一个很深的谷，远超 ±3.5 的阈值线。两处发版带来的小台阶也有反应，但没过阈值——那是真实的业务增长，不该抹平。勾选"对齐口径"：把突变前的数据乘以估计的比例，换算到新口径。估计的比例与真实比例有一点偏差，这很正常，所以正式场合应以"双跑期"的对比数据为准。

处理方式适用情况
双跑校准最可靠：切换前后新老口径并行统计一段时间，直接得到换算比例。要在切换前向数据团队争取
按比例/差值对齐没有双跑期时，用突变点两侧的水平估计比例（上面实验的做法）
加哑变量回归/机器学习模型里加一列"是否新口径"，让模型自己学出台阶高度
只用新口径数据新口径数据已足够长（覆盖 2 个以上完整季节周期）时最干净

尾部未到齐，以及其他几个坑

数据还没"熟"

很多指标不是当天就定型的：订单会取消和退款、离线任务 T+1 甚至 T+3 才跑完、埋点数据延迟上报。于是最近几天的数字系统性偏低，而它们恰恰是模型最看重的"最新信息"。

🧪 实验：最后 3 天没到齐，会发生什么

不处理时，"和上周同一天一样"的朴素预测会把这 3 天的假下跌原样复制到未来。解决办法简单粗暴：训练时截掉还没成熟的尾部，多预测几步补上。成熟期多长要看业务（对比"当天看到的值"和"一周后再看的值"就能量出来）。

节假日错位

春节、中秋按农历走，在公历上每年位置不同。模型如果只知道"几月几号"，就会把去年的春节低谷预测到今年错误的日期上。

年份20222023202420252026
春节（正月初一）2 月 1 日1 月 22 日2 月 10 日1 月 29 日2 月 17 日

正确做法是构造"相对节日的天数"特征（距春节 −7、−6、…、+7 天），让同一个相对位置跨年对齐。调休带来的"周末上班"同理：要用实际的工作日日历，而不是星期几。

间歇性需求

长尾商品可能一周只卖出一两件，序列里大部分是 0。这不是脏数据，但经常被错误处理：把 0 当缺失填掉、或者用 MAPE 评估（实际值为 0 时无法计算）。合适的做法是聚合到更粗的粒度（周、品类）再预测，或使用专门的方法（Croston 及其变体：分别预测"多久卖一次"和"每次卖多少"）。

时区与跨天

服务器用 UTC、业务用北京时间，"一天"的边界差 8 小时；夜间营业的门店把凌晨订单算到哪一天，各系统可能不一致。症状是日数据对不上、或每天固定有一个小时异常。聚合成日粒度之前先统一时区和"营业日"定义。

清洗到底值不值：用预测误差说话

把一份数据弄脏，分别用"脏数据直接训练"和"清洗后再训练"的方式预测未来 28 天，再和真值比。第三根柱子"用真值训练"是理想上限——清洗做得好，应该接近它。

🧪 实验：同一个模型，脏数据 vs 清洗后
未来 28 天的预测误差 MAE（越低越好）
Holt-Winters 的预测：最后 8 周训练数据 + 未来 4 周

脏数据集中注入在最近 180 天。全部勾选时，脏数据上的误差通常是清洗后的数倍。然后点"全部取消"，只留一种问题逐个试："尾部未到齐"的破坏力最大，因为它直接污染模型最依赖的最后几天；其他问题的影响取决于它们离现在多近（多点几次"换一组脏数据"）。几个月前的口径突变对只看近期的模型影响不大，却会带偏用长历史拟合趋势的回归模型。偶尔脏数据的误差反而略低——那是歪打正着，换一组数据就不成立。

清洗流水线与原则

上面实验里用的清洗流程如下。顺序是有讲究的——点击每一步查看原因。

五条原则
  1. 先诊断，再动手。每次拿到新数据先跑体检，量化每类问题有多少，而不是凭感觉 dropna()。
  2. 不覆盖原始值。清洗结果写到新列，并保留 is_imputed、is_outlier、is_stockout 这样的标记列——它们本身就是有用的特征，也方便日后追溯。
  3. 清洗规则不能偷看未来。如果清洗用了未来信息（居中窗口、全局分位数、插值），回测成绩会虚高；线上实时清洗只能用"截至当时"的数据。离线修历史数据可以用双侧信息，但评估时要分清。
  4. 异常先对业务日历。对得上的是事件，保留并做特征；对不上的才清洗。
  5. 规则留痕、可复跑。清洗逻辑写成代码而不是手工改表，每条规则记录"改了多少行、依据是什么"。
Python 参考代码：一条完整的清洗流水线（pandas） 
import numpy as np
import pandas as pd

def clean_daily(raw: pd.DataFrame, calendar: pd.DataFrame, m: int = 7) -> pd.DataFrame:
    """raw: [date, sales, stock_end]；calendar: [date, is_event]。返回带标记列的规整日序列。"""
    # 1) 对齐时间轴：重复行保留最后一条，补全缺失日期
    df = (raw.sort_values("date").drop_duplicates("date", keep="last")
             .set_index("date").asfreq("D"))
    df["raw"] = df["sales"]                        # 原始值永远保留
    y = df["sales"].astype(float)

    # 2) 把"不可信的值"统一置空，并各自打标记
    df["is_missing"]  = y.isna()
    df["is_negative"] = y < 0
    run = (y != y.shift()).cumsum()                # 连续相同值分组
    df["is_flat"]     = y.groupby(run).transform("size").ge(4) & (y == y.shift())
    df["is_stockout"] = df["stock_end"].eq(0)      # 需要库存快照
    y[df["is_negative"] | df["is_flat"] | df["is_stockout"]] = np.nan

    # 3) 截掉未成熟的尾部（成熟期按业务实测，这里假设 3 天）
    y = y.iloc[:-3]; df = df.iloc[:-3]

    # 4) 稳健异常检测：对数尺度上，(滚动中位数 + 星期中位数) 的残差超过 4 倍 MAD
    ly = np.log(y.clip(lower=1))
    trend = ly.rolling(4 * m + 1, center=True, min_periods=m).median()
    seas = (ly - trend).groupby(ly.index.dayofweek).transform("median")
    resid = ly - trend - seas
    mad = 1.4826 * resid.abs().median()
    is_event = calendar.set_index("date")["is_event"].reindex(df.index).fillna(False)
    df["is_outlier"] = (resid.abs() > 4 * mad) & ~is_event     # 事件不算异常
    y[df["is_outlier"]] = np.nan

    # 5) 季节填充：局部水平 × 星期指数
    level = y.rolling(4 * m + 1, center=True, min_periods=m).median()
    index = (y / level).groupby(y.index.dayofweek).transform("median")
    df["is_imputed"] = y.isna()
    df["sales_clean"] = y.fillna(level * index).round()
    return df

clean = clean_daily(raw, calendar)
print(clean.filter(like="is_").sum())              # 每类问题各处理了多少行——留痕

现成的工具：statsmodels.tsa.seasonal.STL(robust=True) 做稳健分解；ruptures 做突变点检测；sktime 的 HampelFilter、Imputer；pandas 的 interpolate(method="time")。

本章要点与小测验

  • 清洗的第一步是对齐时间轴；"行不存在""NaN""0"是三件不同的事，NaN 绝不能当 0。
  • 有季节的数据用季节填充；缺口太长就别硬填。
  • 异常检测用稳健统计量（中位数、MAD），在去掉趋势和季节后的残差上判断。
  • 异常要清洗，事件要保留并做成特征——区分它们靠业务日历，不靠阈值。
  • 销量 ≠ 需求：缺货、限购会截断数据，要还原后再训练。
  • 口径突变要对齐；最近几天的数据可能还没到齐，训练时截掉。
  • 离现在越近的脏数据危害越大。
