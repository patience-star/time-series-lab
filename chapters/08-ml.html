ARIMA 和指数平滑把规律写死在公式里。机器学习换了一个思路：把"预测明天"改写成一道普通的表格回归题——每一行是某一天，列是那一天之前能知道的各种信息（特征），标签是那一天的实际值。之后任何回归模型都能上场，而其中最常胜的是梯度提升树（XGBoost、LightGBM）。这一章讲两件事：特征怎么造，树模型的原理是什么。

把序列变成表格：滑动窗口

做法很机械：拿一个窗口沿着时间轴滑动，窗口里的值当特征 X，窗口后面的值当标签 y。每滑一步，生成一行训练样本。

🧪 实验：滑动窗口生成训练样本

蓝色是特征、橙色是标签。点"下一行"让窗口滑动。窗口越长，每行的信息越多，但能生成的样本越少；预测步长大于 1 时，标签离窗口更远——模型学的是"隔几天之后"的关系。

这一步改写带来三个巨大的好处，也正是机器学习方法在业务预测里流行的原因：

① 特征想加就加

促销、价格、节假日、天气、库存、竞品……只要预测时能拿到，都可以作为一列。ARIMA 很难做到。

② 能学非线性和交互

"周末 × 促销"的效果不是两者之和，树模型能自动学到这种交互。

③ 一个模型管所有序列

把几千个 SKU 的样本堆在一张表里训练一个全局模型，序列之间互相借力，新品也能预测。

特征工程：模型的上限由特征决定

特征类别例子作用注意
滞后昨天、7 天前、14 天前的值提供"最近水平"和"上周期同位置"预测 h 步时，小于 h 的滞后在预测时不可得（要递归或只用 ≥h 的滞后）
滚动统计过去 7/28 天的均值、标准差、最大值平滑的水平、波动大小窗口必须止于昨天，不能包含当天
日历星期几、月份、是否月初/月末、一年中的第几周季节规律永远是"未来已知"的
事件是否促销、折扣力度、距春节天数、是否发版解释尖峰和凹坑要用计划值，且计划要靠谱
周期编码$\sin(2\pi k\,t/365)$、$\cos(\cdot)$（傅里叶项）平滑的长周期季节树模型常用"一年中的第几天"代替
外部变量价格、天气预报、广告投放、库存业务驱动因素未来值未知的只能用预报或滞后值
序列属性品类、门店、城市、上市天数全局模型里区分不同序列高基数类别用 LightGBM/CatBoost 的原生类别支持
🧪 特征工程工坊：勾选特征 → 现场训练 → 看效果
特征重要性（按组汇总）

每次改动都会在浏览器里重新训练一个模型（约 1000 行样本），并对测试段做 28 天的递归预测。建议按这个顺序玩：① 只留"滞后 1"——预测很快变成一条平线；② 加上"滞后 7"和"星期几"——周内节奏出现了；③ 测试时段切到"含一次小促"，再勾选"促销计划"——尖峰被预测到了；④ 切到"含双 11"试试有没有促销特征的区别；⑤ 把特征基本勾全，再把模型切到"岭回归"对比——特征造得好时，简单的线性模型未必输给 GBDT；⑥ 最后勾选"泄漏特征"，看验证误差和真实预测误差如何背道而驰（注意重要性图里那根红色的柱子）。

⚠️ 数据泄漏：时序特征工程的头号杀手

泄漏 = 训练时用了预测时拿不到的信息。它的可怕之处在于：离线验证指标会变好，上线后才崩。三种最常见的形态：

  • 特征偷看未来：rolling(7).mean() 忘了 shift(1)（包含了当天）；居中窗口；用"当日订单数"预测"当日销量"。
  • 切分偷看未来：随机划分训练/验证集（第 05 章）。
  • 统计量偷看未来：用全量数据算均值方差做标准化、算类别的目标编码，然后再切分。

自查方法：对每个特征问一句"站在预测那一刻，这个值我真的已经知道了吗？"；以及警惕重要性异常高的特征。

决策树：用一连串"是/否"问题切分数据

回归树的想法非常朴素：找一个特征和一个阈值，把数据切成两堆，让每一堆内部尽量"整齐"（方差小），然后每一堆用自己的平均值作为预测。切完再对每一堆继续切，直到够深或样本太少为止。

"整齐"的度量是平方误差。一次切分的好坏用方差减少量（增益）衡量：

$$\text{增益} = \underbrace{\sum_{i}(y_i-\bar y)^2}_{\text{切之前}} - \Big[\underbrace{\sum_{i\in \text{左}}(y_i-\bar y_{左})^2 + \sum_{i\in \text{右}}(y_i-\bar y_{右})^2}_{\text{切之后}}\Big]$$

树的训练就是：对每个特征的每个候选阈值算一遍增益，选最大的那个。

🧪 实验：亲手找最佳切分点
气温 → 用电负荷，以及切分后两侧的均值
每个候选切分点的增益

拖动切分点：切在 10°C 这种地方，两侧均值差不多，增益很小；把它拖到右图曲线的最高点（绿色圆点）附近，正好把"大量开空调的热天"和其余的日子分开，增益最大。右图就是树在训练时算的东西——它只是比你拖得更快。

🧪 实验：树越深，阶梯越细——直到开始背答案

树的预测永远是阶梯函数：每个叶子一个常数。深度 1–3 时阶梯逐步逼近真实的弯折形状，测试误差下降；深度继续加大且允许叶子只有 1 个样本时，阶梯开始追逐每一个噪声点——训练误差趋近于 0，测试误差却回升。这就是过拟合。"每个叶子至少多少样本"是最有效的刹车之一。

单棵树的优缺点

优点：不需要特征缩放、天然处理非线性和交互、能解释（一串规则）。缺点：不稳定——数据稍微变一点，切分点就可能大变；单棵树要么太浅（欠拟合）要么太深（过拟合）。解决办法是用很多棵树：随机森林和梯度提升。

随机森林：很多棵树投票

单棵深树的问题是方差大（对训练数据太敏感）。随机森林的对策是"人多力量大"：

  1. 自助采样（bootstrap）：每棵树用有放回抽样得到的一份略有不同的训练集；
  2. 随机选特征：每次切分只在随机抽出的一部分特征里找最佳切分，让树之间更不相像；
  3. 取平均：所有树的预测求平均。各棵树的随机误差互相抵消，结果比任何一棵都稳。
🧪 实验：一棵树 vs 一片森林

细线是单棵树的预测，每一棵都歪歪扭扭、各不相同；粗线是它们的平均，随着树的数量增加越来越平滑、越来越接近真实规律。树加到几十棵之后提升就很小了——随机森林不会因为树多而过拟合，只是越来越慢。

梯度提升树（GBDT）：一棵接一棵地纠错

随机森林的树是并行、独立地种的。梯度提升换了一种组织方式——串行：每一棵新树专门去学前面所有树还没学会的部分（残差）。

$$F_0(x)=\bar y,\qquad r_i = y_i - F_{m-1}(x_i),\qquad h_m \leftarrow \text{用一棵浅树拟合 } r,\qquad F_m(x)=F_{m-1}(x)+\eta\,h_m(x)$$
  • $F_0$：从最朴素的预测（均值）开始；
  • $r_i$：当前模型在每个样本上的残差——还差多少；
  • $h_m$：种一棵很浅的树去预测这些残差；
  • $\eta$：学习率（如 0.1）——每棵树的修正只采纳一小部分，宁可多走几步，不要一步迈太大。

为什么叫"梯度"提升？因为对平方损失 $\tfrac12(y-F)^2$，残差 $y-F$ 恰好是损失对 $F$ 的负梯度。换成别的损失函数（绝对值、分位数），就让新树去拟合那个损失的负梯度——所以它是"在函数空间里做梯度下降"。

训练误差与测试误差随轮数的变化

把轮数拖回 0 再点"播放"。第 0 轮是一条水平线（均值）；右图的残差有明显形状，下一棵树（橙色阶梯）学的就是这个形状；加上去之后残差变小、变得更没规律。几十轮之后残差只剩噪声。再把学习率切到 1：前几轮就拟合得很猛，但测试误差很快掉头向上——学习率小 + 轮数多 + 早停是标准配方。

XGBoost、LightGBM、CatBoost：同一个思想的三种工程实现

原理补充：XGBoost 的"二阶 + 正则"到底改了什么 
GBDT（本页实现）：叶子值 = 落在该叶子里的残差的平均值
                  增益   = 方差减少量

XGBoost：对任意损失函数 L，在当前预测处做二阶泰勒展开，
         记 g_i = 一阶导数（梯度），h_i = 二阶导数（海森），则

         叶子的最优值  w* = − Σg_i / (Σh_i + λ)
         切分的增益    = ½ [ GL²/(HL+λ) + GR²/(HR+λ) − (GL+GR)²/(HL+HR+λ) ] − γ

         λ：L2 正则，让叶子值向 0 收缩（样本少的叶子不敢给太大的修正）
         γ：每多一个叶子要付的"门槛费"，增益不够就不切

平方损失时 g_i = −残差，h_i = 1，λ=0、γ=0 就退化成上面的 GBDT。
好处：① 换损失函数不用重新推导；② 正则直接写进了切分准则里。

LightGBM 的直方图：把每个特征的取值预先分成 ≤255 个桶，
         找切分时不再遍历所有取值，只遍历桶 → 速度提升一个数量级。
         （本页面的树就是这样实现的，用了 32 个桶）
超参数（LightGBM 名称）作用经验
learning_rate + n_estimators每棵树的步长、树的数量学习率 0.03–0.1；树的数量用早停在按时间切分的验证集上自动确定
num_leaves / max_depth单棵树的复杂度从 31 / 不限开始；数据少就调小
min_data_in_leaf叶子最少样本数时序数据噪声大，常设 20–200

objective损失函数regression（L2）、regression_l1、quantile（分位数预测）、tweedie（大量 0 的间歇需求）

树模型的致命弱点：不会外推

树的预测是叶子里训练样本的平均值，所以它永远给不出比训练集里见过的最大值更大的预测。业务量在增长时，这是个大问题。

🧪 实验：持续上涨的序列，GBDT 撞上天花板

默认设置下，预测在训练集的最高水平附近"撞墙"，只会重复季节形状，完全跟不上趋势。勾选"预测相对变化"后，目标和滞后特征都改成"相对最近 7 天均值的差"——模型学的不再是"水平是多少"，而是"比最近的水平高或低多少"，这在任何水平上都成立，于是趋势回来了。

💡 让树模型跟上趋势的常用办法
  • 改目标：预测差分、增长率、或"相对最近均值的比例"（上面实验的做法），预测完再还原。
  • 先去趋势：用线性模型或指数平滑拟合趋势，树模型只学残差（"线性 + 树"的混合）。
  • 相对化特征：滞后值除以滚动均值，让特征和目标都与水平无关。
  • 目标取对数只能把指数增长变成线性增长，不能单独解决外推问题。

多步预测的策略

模型一次只输出一个数，但业务要未来 28 天。怎么办？

策略做法优点缺点
递归训练一个"预测下一步"的模型；预测出来的值当作已知，再预测下一步只需一个模型；能用最近的滞后误差逐步累积，越远越差
直接每个步长训练一个模型（或只使用 ≥h 天前的信息）没有误差累积模型多；用不上最近几天的信息
多输出一个模型同时输出 h 个值各步之间保持一致树模型不直接支持，神经网络常用（第 10 章）
🧪 实验：预测得越远，误差越大吗？

这是在 8 个不同时间点回测、按"提前几天预测"汇总的平均误差。递归法在前几天最准（它用到了昨天的真实值），但误差随步长上升；"直接法"只用 28 天前及更早的信息，短期不如递归，但误差不随步长恶化。实践中常把两者结合：近期用递归，远期用直接。

全局模型、Prophet，以及什么时候用机器学习

全局模型

传统方法给每条序列各建一个模型（局部模型）。机器学习的典型用法是把所有序列的样本堆进一张表，加上"品类、门店、城市"等属性列，训练一个模型。好处：数据量大了几个数量级；相似商品互相借力；新品没有历史也能靠属性预测。要点：

  • 尺度归一：不同序列量级差几千倍，要把目标和滞后特征除以各自的平均水平（或取对数、预测相对变化）。
  • 验证仍按时间切分，所有序列用同一个时间点切。
  • 评估用 WAPE / MASE 这类跨序列可比的指标。

Prophet 是什么

Prophet 是一个流行的预测库，它的模型是 $y(t) = g(t) + s(t) + h(t) + \varepsilon$：分段线性的趋势 $g$、用傅里叶项表示的季节 $s$、节假日效应 $h$。本质上是一个精心设计了特征的加法回归模型——没有滞后项，完全靠"时间"和"日历"来解释数据。优点是上手快、对缺失和异常宽容、能方便地加节假日；缺点是不利用近期的自相关，短期预测精度常常不如带滞后特征的模型或 ETS/ARIMA。适合做有强节假日效应的中长期预测和快速基线。

情况更适合
单条序列、数据不长、没有外部变量ETS / ARIMA（第 06、07 章）
有促销、价格、天气等驱动因素GBDT + 特征工程
成百上千条相关序列全局 GBDT（或深度学习，第 10–11 章）
需要严格的统计推断和可解释系数ARIMAX / 回归
有强趋势需要外推统计模型，或"去趋势 + GBDT"
Python 参考代码：特征工程 + LightGBM + 时间切分验证 + 递归预测 
import numpy as np, pandas as pd, lightgbm as lgb

def make_features(df):                      # df: 索引为日期，列 [y, promo, is_holiday]
    f = pd.DataFrame(index=df.index)
    ly = np.log1p(df["y"])
    for k in (1, 7, 14, 28):
        f[f"lag{k}"] = ly.shift(k)
    past = ly.shift(1)                      # 关键：先 shift(1)，窗口才不包含当天
    for w in (7, 28):
        f[f"mean{w}"] = past.rolling(w).mean()
        f[f"std{w}"]  = past.rolling(w).std()
    f["dow"], f["month"] = df.index.dayofweek, df.index.month
    f["promo"], f["holiday"] = df["promo"], df["is_holiday"]      # 未来已知的计划
    return f, ly

X, ly = make_features(df)
ok = X.notna().all(axis=1)
X, ly = X[ok], ly[ok]

cut = X.index[-56]                          # 按时间切分：最后 8 周做验证
Xtr, ytr, Xva, yva = X[X.index < cut], ly[ly.index < cut], X[X.index >= cut], ly[ly.index >= cut]

model = lgb.LGBMRegressor(n_estimators=2000, learning_rate=0.05, num_leaves=31,
                          min_child_samples=30, subsample=0.8, subsample_freq=1,
                          colsample_bytree=0.8, objective="regression")
model.fit(Xtr, ytr, eval_set=[(Xva, yva)], eval_metric="l1",
          categorical_feature=["dow", "month"],
          callbacks=[lgb.early_stopping(100), lgb.log_evaluation(200)])

imp = pd.Series(model.feature_importances_, X.columns).sort_values(ascending=False)
print(imp.head(10))                         # 某个特征高得离谱？先怀疑泄漏

                  freq="D", lags=[1, 7, 14, 28],
                  lag_transforms={1: [RollingMean(7), RollingMean(28)]},
                  date_features=["dayofweek", "month"])

本章要点与小测验

  • 滑动窗口把预测变成表格回归；滞后、滚动、日历、事件是四类基本特征。
  • 每个特征都要问：预测那一刻真的已经知道了吗？泄漏会让验证变好、上线变差。
  • 回归树 = 反复寻找方差减少量最大的切分；预测是阶梯函数；深了会过拟合。
  • 随机森林：并行种很多树取平均，降方差。GBDT：串行地让每棵浅树拟合残差，小学习率 + 早停。
  • XGBoost 加了二阶信息和正则；LightGBM 用直方图和按叶子生长，速度最快。
  • 树模型不会外推趋势——预测相对变化或先去趋势。
  • 多步预测：递归会累积误差，直接法不会但用不上最新信息。
