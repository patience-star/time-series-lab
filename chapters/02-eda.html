拿到一条时间序列，第一件事永远是画出来看。这一章介绍四件探索工具：移动平均看趋势、季节图看节奏、分解把成分拆开、滞后图看"记忆"。它们既是建模前的侦察，也是日常业务分析里最常用的手段。

先画图：看什么

看一条曲线时，按下面的清单逐项过一遍，基本就知道后面该用什么方法了：

看什么怎么看看到之后意味着
趋势整体在涨、跌还是持平？是直线还是在拐弯？模型要有趋势项，或先做差分（第 04 章）
季节有没有固定间隔的重复？周期是 7、12、24 还是多个叠加？决定季节周期参数 $m$
波动幅度波动随水平变大而变大吗？是 → 乘法模型或先取对数
尖峰与凹坑个别点特别高或特别低？能对上促销/节假日吗？对得上是事件，对不上要查是否异常（第 03 章）
结构变化某个时间点前后，水平或规律突然不一样？可能是口径变更或业务变化，老数据未必还能用
缺口有没有断线、连续的 0、一段平线？数据质量问题，先清洗（第 03 章）

移动平均：把噪声抹掉看趋势

移动平均（Moving Average）用一个窗口内的平均值代替每个点，噪声和短周期波动互相抵消，趋势就浮现出来。看板上常见的"7 日均线""28 日均线"就是它。

$$\text{居中：}\; \hat T_t = \frac{1}{w}\sum_{j=-k}^{k} y_{t+j}\;(w = 2k+1) \qquad \text{只看过去：}\; \hat T_t = \frac{1}{w}\sum_{j=0}^{w-1} y_{t-j}$$
🧪 实验：移动平均的窗口该取多大

试一试：① 窗口从 1 慢慢拉到 7——到 7 的那一刻曲线突然变得很平，因为窗口刚好盖住一个完整的周，周内的高低正好抵消；② 窗口取 5 或 10，曲线反而有残留的锯齿；③ 切到"只看过去"，注意均线比真实走势慢半拍——窗口越大滞后越多。

两条经验
  • 窗口取季节周期的整数倍（7、14、28；12、24），才能把季节抹干净。
  • 居中平均用于事后分析（它用到了未来的值）；实时监控和做特征只能用"只看过去"的版本，代价是滞后。把居中平均当特征喂给模型是一种典型的数据泄漏（第 08 章）。

季节图：把每个周期叠在一起看

把数据按"在周期中的位置"分组——星期几、几点钟、几月份——节奏就一目了然。为了不让趋势干扰，下面的图用的是相对趋势的比例（实际值 ÷ 居中移动平均），1.0 表示"和平均水平一样"。

💼 季节图在业务里的用法
  • 排班与备货节奏：周六比周二高多少，直接决定各天的人手和到货量。
  • 发现节奏变化：叠线图里新周期（深色）和老周期（浅色）形状不一样，说明用户行为变了，老的季节规律要打折。
  • 盒子特别长的位置说明那天波动大（比如周五有时赶上促销），预测时要给更宽的区间。

分解：把趋势、季节、残差拆开

经典分解的做法只有三步，全部由上面两个工具组成：

  1. 趋势 = 窗口为一个周期的居中移动平均；
  2. 季节 = 去掉趋势后，按周期位置求平均（就是季节图的中心线），再归一化；
  3. 残差 = 观测值去掉趋势和季节之后剩下的部分。

加法模型里"去掉"是减法，乘法模型里是除法。分解得好不好，看残差：好的残差应该是没有规律的小幅波动；如果残差里还能看出周期或喇叭口，说明模型形式选错了。

经典分解的局限与 STL

经典分解简单直观，但有三个硬伤：首尾各丢半个周期（居中平均算不出来）；假设季节形状永远不变；对异常值敏感（一个双 11 会把周围的趋势拉高）。实际工作中更常用 STL（Seasonal-Trend decomposition using LOESS）：

  • 用局部加权回归（LOESS）代替移动平均，首尾也有值；
  • 季节成分可以随时间缓慢变化；
  • 有稳健模式，异常点会被自动降权，不会污染趋势和季节；
  • 多重季节（比如小时数据同时有日周期和周周期）用它的扩展 MSTL。
Python 参考代码：经典分解、STL、MSTL 
from statsmodels.tsa.seasonal import seasonal_decompose, STL, MSTL

# 经典分解（乘法）
res = seasonal_decompose(y, model="multiplicative", period=7)
res.plot()

# STL：只支持加法，乘法结构先取对数；robust=True 抵抗异常值
import numpy as np
stl = STL(np.log(y), period=7, robust=True).fit()
trend, seasonal, resid = stl.trend, stl.seasonal, stl.resid

# 小时数据：日周期 24 + 周周期 168
mstl = MSTL(load, periods=(24, 24 * 7)).fit()

# 季节强度（0~1）：越接近 1 季节越明显
strength_s = max(0, 1 - resid.var() / (seasonal + resid).var())

滞后图：今天和 k 天前有多像

把每个点的值 $y_t$ 和它 $k$ 步之前的值 $y_{t-k}$ 配成一对画散点图，就是滞后图。点越集中在一条斜线上，说明"$k$ 天前的值"对今天越有预测力。这种相关性的强度就是自相关系数 $r_k$，第 04 章会系统地讲。

保持"先去掉趋势"勾选，把滞后从 1 拉到 14：到 7 和 14 时散点收拢成一条斜线，这就是周季节；滞后 3、4 时反而是负相关（周末对上了工作日）。然后取消勾选：所有滞后都高度相关——那是趋势造成的假象（早期低、后期高，任意两天都"同高同低"）。所以看自相关之前要先处理趋势。换成"电商销量"再看：大促和春节会让散点图多出一些离群点。

业务最常用的对比：环比与同比

业务周报里最常见的两个数是环比（和上一期比）和同比（和上一个周期的同一位置比）。它们本质上就是滞后 1 和滞后 $m$ 的变化率——而选错了滞后，看到的全是季节噪声。

🧪 实验：日活的"日环比"为什么没法看

日环比每周规律性地上蹿下跳（周六比周五高、周一比周日低），真正的异常被淹没在里面；换成"周同比"（和上周同一天比），季节被抵消，曲线贴着 0 走，那次故障造成的下跌一眼就能看见。

⚠️ 同比也有坑
  • 节假日错位：春节每年公历日期不同，1–2 月的同比天然失真；应按"距春节第几天"对齐后再比。
  • 基数效应：去年同期如果有大促或故障，今年同比会被动地显得很差或很好。
  • 星期错位：按日期做年同比时，去年同一天可能是周末而今年是工作日；日粒度应按"去年同一周的同一个星期几"对齐。
Python 参考代码：移动平均、环比同比、滞后图、自相关 
import pandas as pd
from pandas.plotting import lag_plot, autocorrelation_plot

ma7  = y.rolling(7).mean()                 # 只看过去的 7 日均线（可用于实时/特征）
ma7c = y.rolling(7, center=True).mean()    # 居中（只用于事后分析）

dod = y.pct_change(1)                      # 日环比
wow = y.pct_change(7)                      # 周同比（和上周同一天比）
yoy = y.pct_change(364)                    # 年同比：用 364 天对齐星期几，而不是 365

lag_plot(y, lag=7)                         # 滞后散点图
print(y.autocorr(lag=7))                   # 滞后 7 的自相关系数

# 按星期几看季节（先除以趋势）
ratio = y / ma7c
print(ratio.groupby(ratio.index.dayofweek).describe())

本章要点与小测验

  • 移动平均的窗口取季节周期的整数倍；居中版本用了未来信息，只能用于事后分析。
  • 季节图 = 按周期位置分组看分布，先除掉趋势再看更干净。
  • 分解 = 趋势（移动平均）+ 季节（按位置平均）+ 残差；残差有没有规律是检验分解/模型的标准。
  • 实际工作优先用 STL（稳健、季节可变）；多重季节用 MSTL。
  • 看自相关、看环比之前先处理趋势和季节，否则看到的是它们的影子。
