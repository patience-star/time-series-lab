在学任何"高级"模型之前，先学会两件更重要的事：拿什么当参照物（基线），以及怎么公平地打分（回测与指标）。评估方法错了，后面所有的模型对比都是自欺欺人。这一章的内容会被之后每一章反复用到。

四个基线：任何模型都要先打败它们

基线是不需要"训练"的最简单预测方法。它们的意义是给出一个底线：如果一个复杂模型连基线都打不过，它就不值得上线。

基线预测值适用业务里的叫法
均值法历史平均值平稳、无趋势无季节"按历史平均来"
朴素法最后一个观测值 $\hat y_{T+h}=y_T$随机游走类数据（股价、汇率）"和昨天一样"
季节朴素法上个周期同一位置 $\hat y_{T+h}=y_{T+h-m}$季节明显的数据"和上周同一天一样""和去年同期一样"
漂移法最后一个值 + 历史平均增量 × $h$有稳定趋势"按平均增速往上推"
🧪 实验：四个基线同台竞技

切换数据看谁赢：电商销量和日活上季节朴素明显领先；股价上谁也赢不了朴素法（上一章说过，随机游走的最佳预测就是当前值）；月度销售额既有趋势又有季节，四个基线都不够好——这正是后面要学更强模型的理由。

💼 向业务方汇报模型效果时

不要只说"我们的模型 MAPE 是 12%"——没有参照物，这个数字没有意义。应该说"现在大家用的'和上周一样'误差是 18%，新模型是 12%，误差下降三分之一"。相对基线的提升才是模型的价值。

切分数据：只能用过去预测未来

普通机器学习习惯随机抽 20% 当测试集。时间序列绝对不能这样做：随机抽出的测试点，前一天和后一天都在训练集里，模型等于"看着答案的邻居做题"。

🧪 实验：随机切分为什么会骗人

数据是上一章的股价（随机游走，本来就几乎不可预测）。这里的"模型"故意做得很傻：预测某一天时，直接取训练集里时间上最近的两个点求平均。随机切分下它"预测"得非常准——因为它总能找到紧挨着的前一天和后一天；换成时间切分（测试集全在未来），它只能拿最后见过的两天来猜，原形毕露。网上不少"模型预测股价准确率 99%"的结果就是这么来的。上线后面对的永远是右边这种情况。

滚动起点回测：模拟"上线后每次预测"

只切一刀、测一次，结果很依赖那一段时间碰巧好不好预测。更可靠的做法是滚动起点回测（也叫时间序列交叉验证、walk-forward）：站在历史上的多个时间点，每次都只用当时能看到的数据训练，预测之后的 $h$ 步，再和真实值比。

🧪 实验：一折一折地回测
每一折用到的数据（蓝 = 训练，橙 = 测试）
当前这一折：季节朴素法的预测 vs 实际

点"下一折"逐折查看。注意各折的误差并不一样——赶上促销的那一折误差会大很多。所以汇报时除了平均值，也要看最差的一折：它代表模型在最不利时期的表现。"滑动窗口"只用最近一段训练，适合老数据已经过时的情况。

回测设计的四个参数
  • 预测步长 $h$：必须等于业务真正需要的步长（提前 14 天订货，就回测 14 步）。
  • 折数：越多越稳，但越慢。日数据常用 5–10 折。
  • 步进：相邻两折的起点间隔，通常等于 $h$（测试段不重叠）。
  • 覆盖范围：测试段合起来最好覆盖一个完整的季节周期和至少一次大促，否则不知道模型在这些时期的表现。

评估指标：每个指标都有自己的"脾气"

设实际值为 $y_t$，预测值为 $\hat y_t$，误差 $e_t = \hat y_t - y_t$：

指标公式优点脾气
MAE$\frac1n\sum|e_t|$单位和原数据一致，好解释不同量级的序列之间不能比
RMSE$\sqrt{\frac1n\sum e_t^2}$重罚大误差对个别离群点非常敏感
MAPE$\frac1n\sum\left|\frac{e_t}{y_t}\right|$百分比，业务方最熟悉实际值接近 0 时爆炸；低估最多罚 100%、高估没有上限，用它选模型会偏向低估
sMAPE$\frac1n\sum\frac{2|e_t|}{|y_t|+|\hat y_t|}$有上界（200%）名字叫"对称"其实不对称（同样的偏差幅度，低估罚得更重）；实际值为 0 时恒为 200%
WAPE$\frac{\sum|e_t|}{\sum|y_t|}$按量加权，零值不怕；零售业首选大销量的日子主导结果
MASE$\frac{\text{MAE}}{\text{训练集上季节朴素法的 MAE}}$无量纲，<1 即优于朴素法；跨序列可比不直观，需要解释
Bias$\frac1n\sum e_t$看系统性高估还是低估正负会抵消，不能单独用
🧪 指标实验室：给预测"加料"，看各指标的反应

① 先把"随机误差"调到 0，只调"系统性偏差"：+20% 和 −20% 时 MAE、MAPE 都一样，sMAPE 却不一样——它并不像名字说的那样对称。② 把随机误差调回来，勾选"一个离群点"：RMSE 暴涨，MAE 涨得少得多。③ 勾选"接近 0 的实际值"：MAPE 直接失控（两个小数字上的误差被放大成百分之几千），WAPE 几乎不动。这就是为什么零售行业普遍用 WAPE 而不是 MAPE。

业务场景推荐指标原因
单条序列，给业务方看MAE + WAPE一个有单位、一个是百分比，都好解释
很多 SKU / 门店汇总评估WAPE（按销量加权）、MASE不被小销量商品的百分比误差绑架
大误差代价特别高（电力调峰）RMSE，另加"峰值时段误差"重罚大偏差
缺货和积压代价不对称分位数损失（见下文）+ Bias直接对应业务成本
间歇性需求（大量 0）MASE、WAPE；避免 MAPEMAPE 无法计算

预测区间：承认不确定性

点预测只给一个数，但未来是不确定的。预测区间给出一个范围和一个把握程度："未来 14 天的日销量有 95% 的可能落在这个带子里"。区间有两个要求：

  • 校准：说 95% 就应该真的有约 95% 的实际值落在里面（这个比例叫覆盖率）；
  • 尽量窄：一个宽到没有信息量的区间永远"正确"，但毫无用处。
🧪 实验：预测区间与实际覆盖率

拖动置信水平，带子变宽变窄。更关键的是"实际覆盖率"：它是在过去 16 个时间点反复回测统计出来的，经常和名义值对不上。偏窄（覆盖率低于名义值）在真实项目里最常见——公式只算了随机噪声，没算模型本身可能是错的；偏宽也会发生——比如历史上的大促尖峰把"噪声大小"的估计撑大了，平常日子的区间就显得过于保守。无论哪种，结论都一样：模型自带的区间不能直接信，要用回测检验，并用回测误差的经验分位数来校准（这类方法叫保形预测，conformal prediction）。

评估区间和分位数预测，用分位数损失（pinball loss）。对分位数 $\tau$（比如 0.9）：

$$L_\tau(y,\hat q)=\begin{cases}\tau\,(y-\hat q) & y\ge \hat q\;\text{（预测低了）}\\ (1-\tau)\,(\hat q-y) & y<\hat q\;\text{（预测高了）}\end{cases}$$

$\tau=0.9$ 时，低估一件的惩罚是高估一件的 9 倍——于是最小化这个损失的预测，自然会落在"有 90% 把握不会低估"的位置。$\tau=0.5$ 时它就是 MAE。

从预测到决策：报童模型

预测出"明天需求大约 1000 件"，是不是就该备 1000 件？不一定。如果缺货一件损失 40 元毛利，而多备一件只损失 10 元，那多备一些显然更划算。这个经典问题叫报童模型：

$$q^* = F^{-1}\!\left(\frac{C_u}{C_u + C_o}\right)$$

其中 $C_u$ 是缺货成本（少备一件的损失），$C_o$ 是积压成本（多备一件的损失），$F^{-1}$ 是需求分布的分位数函数。也就是说：最优备货量是需求分布的某个分位数，而这个分位数完全由两种成本的比例决定。

🧪 实验：缺货贵还是积压贵？
不同备货量下的期望成本（需求预测：均值 1000 件）

① 两种成本相等时，最优备货量 = 预测均值。② 把缺货成本调高（高毛利、缺货会流失客户）：最优点右移，多出来的部分就是安全库存。③ 把积压成本调高（生鲜、时装）：最优点左移，宁可卖断货。④ 把"预测不确定性"调大：成本曲线整体抬高——预测得越不准，越要多付成本，这就是提升预测精度在财务上的价值。

💼 这对预测工作意味着什么
  • 业务要的往往不是"最可能卖多少"，而是"备多少最划算"——这需要分位数预测，而不只是点预测。
  • 评估指标应贴合成本结构：缺货更贵的业务，低估比高估更该被惩罚（用 $\tau > 0.5$ 的分位数损失）。
  • 对预测区间的校准要求是实打实的：区间偏窄 → 安全库存算少 → 缺货率高于设计值。

残差诊断：模型还剩下什么没学到

指标告诉你模型"有多准"，残差（实际 − 拟合）告诉你它"哪里不准"。合格的残差应满足：

检查怎么看不满足说明
均值为 0Bias 接近 0系统性高估/低估——直接加个修正量就能变准
没有自相关残差的 ACF 落在虚线带内；Ljung-Box 检验 p 值不小还有规律没被模型利用（第 07 章会用到）
方差恒定残差大小不随时间或水平变化区间在某些时期偏窄；考虑对数变换
按维度无偏分星期几、分是否促销看 Bias比如"周末总是低估"——缺了对应的特征
Python 参考代码：基线、滚动回测、指标 
import numpy as np
import pandas as pd

# ---------- 指标 ----------
def wape(y, f):  return np.abs(f - y).sum() / np.abs(y).sum()
def mase(y, f, y_train, m=7):
    scale = np.abs(y_train[m:] - y_train[:-m]).mean()      # 训练集上季节朴素的 MAE
    return np.abs(f - y).mean() / scale
def pinball(y, q, tau):
    u = y - q
    return np.mean(np.where(u >= 0, tau * u, (tau - 1) * u))

# ---------- 基线 ----------
def seasonal_naive(train, h, m=7):
    return np.array([train[len(train) - m + (i % m)] for i in range(h)])

# ---------- 滚动起点回测 ----------
def backtest(y, model, h=14, folds=6, step=None, m=7):
    step = step or h
    rows = []
    for k in range(folds - 1, -1, -1):
        cut = len(y) - h - k * step
        train, test = y[:cut], y[cut:cut + h]
        f = model(train, h)
        rows.append({"cut": cut, "MAE": np.abs(f - test).mean(),
                     "WAPE": wape(test, f), "MASE": mase(test, f, train, m),
                     "Bias": (f - test).mean()})
    return pd.DataFrame(rows)

res = backtest(y.values, seasonal_naive)
print(res.round(3)); print(res.mean().round(3))

本章要点与小测验

  • 先建基线（季节数据用季节朴素法）；模型的价值 = 相对基线的提升。
  • 时间序列只能按时间切分；随机切分会让模型偷看到未来的邻居。
  • 滚动起点回测：多个起点、步长等于业务步长、看平均也看最差的一折。
  • RMSE 怕离群点，MAPE 怕接近 0 的实际值且不对称；零售多用 WAPE，跨序列比较用 MASE。
  • 预测区间要校准；模型自带的区间未必可信，要用回测检验实际覆盖率。
  • 备多少货是决策问题：最优备货量是需求分布的 $C_u/(C_u+C_o)$ 分位数。
