LSTM 靠"一步一步传话"来记住过去，传得再好也是接力。注意力机制换了一个思路：不传话了，需要哪一天的信息，就直接回头去看那一天。完全由注意力搭起来的网络就是 Transformer——大语言模型的基础，也是近几年时间序列预测模型和"时序大模型"的基础。这一章讲清注意力的原理、它用在时间序列上遇到的问题和解决办法（分块），以及什么时候才值得上深度学习。

LSTM 还有什么不够好

信息要层层转手

想用到 60 天前的信息，它得在细胞状态里"存活"60 步。门控让这成为可能，但仍然会损耗。

没法并行

第 t 步必须等第 t−1 步算完。序列一长，训练就慢，很难扩展到海量数据。

看不出它在看哪

所有历史被压进一个向量里，很难解释模型到底参考了哪些日子。

注意力机制同时解决了这三点：任意两个位置之间一步直达；所有位置可以同时计算；注意力权重本身就告诉你模型在看哪里。

注意力：按相似度加权平均

注意力只做一件事：拿着一个"问题"，去一堆"记录"里找最相关的几条，把它们的"内容"按相关程度加权平均。三个角色：

角色含义在"预测明天销量"里
查询 Query $q$我现在想找什么最近 7 天的销量形状
键 Key $k_i$每条记录的"索引标签"历史上每一个 7 天窗口的形状
值 Value $v_i$每条记录的"内容"那个窗口之后的第二天发生了什么
$$\text{权重}\;\; w_i = \frac{\exp\big(\text{相似度}(q, k_i)/\tau\big)}{\sum_j \exp\big(\text{相似度}(q, k_j)/\tau\big)}\qquad\qquad \text{输出} = \sum_i w_i\, v_i$$

中间那一步叫 softmax：把一组相似度分数变成一组加起来等于 1 的正数权重。$\tau$ 是温度：温度低，权重集中在最相似的少数几条上；温度高，权重摊平，接近普通平均。Transformer 里的相似度用的是向量点积 $q\cdot k_i$，并除以 $\sqrt{d}$（向量维度的平方根）来控制尺度，所以叫"缩放点积注意力"。

🧪 实验：用注意力做预测——模型在看历史上的哪些日子
销量历史（阴影 = 查询窗口，竖线 = 要预测的那一天）
注意力权重：预测时参考了历史上每一天的多少

这是一个没有任何可训练参数的"纯注意力"预测器：找出历史上和"最近这一周"形状最像的那些周，看它们的下一天是什么样，加权平均。① 温度调低：权重集中成几根尖刺，而且几乎都落在和目标日同一个星期几的日子上——注意力自己"发现"了周季节；② 温度调高：权重摊平到所有日子，预测退化成"最近的平均水平"；③ 拖动"预测哪一天"，看尖刺如何跟着移动。真正的 Transformer 和它的区别只是：相似度怎么算（Q、K、V 各经过一个可学习的线性变换）是从数据里学出来的。

自注意力：让序列里的每个位置互相看

上面是"拿最后一段去查历史"。自注意力更进一步：让输入序列里的每一个位置都作为查询，去看序列里的所有位置，得到一个融合了上下文的新表示。$L$ 个位置两两之间的权重排成一个 $L\times L$ 的注意力矩阵：第 $i$ 行表示"位置 $i$ 在更新自己时，从其他各个位置各取了多少"。

$$\text{Attention}(Q,K,V)=\text{softmax}\!\left(\frac{QK^{\top}}{\sqrt{d}}\right)V,\qquad Q = XW_Q,\;\; K = XW_K,\;\; V = XW_V$$

$X$ 是输入（每行一个位置的向量），$W_Q, W_K, W_V$ 是三个可学习的矩阵——模型通过它们学会"什么样的两个位置算相关"。

🧪 实验：28 天销量的自注意力矩阵

横轴和纵轴都是这 28 天；颜色越深表示注意力越大。切换"按什么算相似"：数值相近——销量水平接近的日子互相关注（周末看周末）；位置相邻——只看自己附近几天，矩阵是一条沿对角线的带子，相当于一个局部平滑；星期相同——出现间隔为 7 的平行条纹。真实的 Transformer 有多个注意力头，每个头学一种不同的"相关"，就像这三张图同时存在。

位置编码：告诉模型"谁在前谁在后"

注意力只看内容相似度，对顺序是"脸盲"的：把输入打乱，它算出的结果只是跟着打乱而已。而时间序列的顺序恰恰是全部信息所在。所以必须给每个位置加上一个表示"我在第几位"的向量——位置编码。经典做法是用不同频率的正弦和余弦：

$$PE_{(pos,\,2i)} = \sin\!\Big(\frac{pos}{10000^{2i/d}}\Big),\qquad PE_{(pos,\,2i+1)} = \cos\!\Big(\frac{pos}{10000^{2i/d}}\Big)$$
🧪 实验：位置编码长什么样

每一列是一个位置的编码向量。上面几行（低维度）变化很快，能区分相邻的位置；下面几行变化很慢，能区分相距很远的位置。合在一起，每个位置都有一个独一无二的"条形码"。时间序列模型里也常用可学习的位置编码，或者直接把日历信息（星期几、几月、几点）编码进去。

把 Transformer 直接搬到时间序列上，会遇到什么

Transformer 在语言上大获成功之后，研究者很自然地把它用到了时间序列上（Informer、Autoformer 等一系列模型）。但时间序列和语言有三个关键差别：

差别后果
一个时间点 ≠ 一个词：单独一个"周二销量 1340"几乎没有语义，信息在一段的形状里逐点做注意力，是在比较没什么意义的单个数值
序列很长：要覆盖年季节，日数据需要几百个点，小时数据上千个$L^2$ 的计算量和内存吃不消
数据少、噪声大：一条序列几百上千个点，远不如文本语料丰富大模型很容易过拟合
⚠️ 一个著名的"打脸"实验

2022 年的论文《Are Transformers Effective for Time Series Forecasting?》提出了 DLinear：把序列分解成趋势和季节两部分，各接一层线性回归，没有注意力、没有非线性。结果在当时主流的长期预测基准上，它超过了多个结构复杂的 Transformer 变体。这篇文章的价值不在于"线性模型最好"，而在于提醒大家：时间序列预测里，复杂模型必须和简单基线同台比较——这正是本教程从第 05 章起一直强调的事。

分块（Patching）：PatchTST 的思路

2023 年的 PatchTST 给出了一个简单有效的回应，核心就两点：

  1. 分块：不把单个时间点当作 token，而是把序列切成一段一段的小块（比如每 16 个点一块），每个块经过一个线性层变成一个 token。这和视觉 Transformer 把图片切成小方块是同一个想法。
  2. 通道独立：多变量序列的每个变量单独过同一个模型（共享权重），而不是在一开始就混在一起。

分块一举解决了前面的两个问题：每个 token 是"一段形状"，有了语义；token 数量减少为原来的几分之一，注意力的计算量按平方下降，于是可以看更长的历史。

🧪 实验：分块如何改变 token 数和计算量

数据是电力小时负荷。块长设为 24：每个 token 恰好是一整天的负荷曲线——模型比较的是"这一天的形状"和"那一天的形状"，比比较两个单独的小时有意义得多。把块长调回 1（逐点），token 数等于窗口长度，注意力要计算的"位置对"数量暴涨。相邻块之间留一些重叠（步长小于块长）可以避免规律被切断在块的边界上。

时序大模型：预训练一次，到处零样本预测

语言模型的路线是"在海量文本上预训练一个大模型，然后直接拿来用"。2023 年起，同样的思路被搬到了时间序列上：在几十亿到上千亿个时间点（各行各业的公开数据加上合成数据）上预训练一个 Transformer，拿到一条它从没见过的新序列，不做任何训练就直接预测——这叫零样本（zero-shot）预测。

模型来自核心做法
ChronosAmazon把数值缩放后量化成离散的"词"，直接用语言模型的架构（T5）来训练；通过采样得到概率预测。后续的 Bolt 版本改用分块，速度快很多
TimesFMGoogle分块 + 只有解码器的 Transformer（类似 GPT），直接输出未来一段
MoiraiSalesforce支持任意数量的变量和多种频率，输出灵活的概率分布
Lag-Llama学术界开源用滞后值作为输入特征的解码器模型，概率预测
TimeGPTNixtla闭源，通过 API 调用

✅ 好处

不用训练、不用调参，几行代码出结果；对短序列、冷启动的新品尤其有用（传统方法没法训练）；自带概率预测。

⚠️ 局限

不了解你的业务：不知道促销计划、节假日安排（部分模型开始支持协变量）；在特定领域的数据上，认真调过的 GBDT 或统计模型常常仍然更准；模型大，推理成本高。

🧭 怎么用

把它当作一个很强的、零成本的基线加入回测；数据很少时作为主力；也可以在自己的数据上微调。

下面这些模型你会在论文、库和面试里碰到。知道它们各自的定位即可，原理都建立在前面讲过的零件之上。

什么时候才值得上深度学习

你的情况建议
一条或几条序列，每条几百上千个点不要从深度学习开始。ETS / ARIMA / GBDT 更准、更快、更好解释
几百到几万条相关序列，有协变量全局 GBDT 是首选基线；DeepAR / TFT / PatchTST 值得放进回测对比
海量序列（十万级以上）、高频数据、复杂的跨序列关系深度学习开始显出优势
新品、新店，历史极短全局模型（靠属性特征）或时序大模型的零样本预测
需要完整的概率分布DeepAR、分位数回归的 GBDT、时序大模型
需要向业务方解释每个预测统计模型或 GBDT + 特征重要性；深度模型里 TFT 的可解释性相对较好
💡 一条贯穿始终的原则

不要因为模型"先进"而选它。把候选模型和简单基线放进同一套滚动回测（第 05 章），用贴合业务代价的指标比较，再考虑训练成本、维护成本和可解释性。下一章的模型竞技场就是这么做的。

    ],
    freq="D",

# long_df：长表格式 [unique_id, ds, y, promo, is_holiday]，多条序列堆在一起做全局训练

本章要点与小测验

  • 注意力 = 用查询去和所有键比相似度，softmax 成权重，对值加权平均；任意两个位置一步直达。
  • 自注意力让序列里每个位置都去看所有位置；多头 = 同时学多种"相关"。
  • 注意力不知道顺序，必须加位置编码。
  • Transformer = 自注意力 + 前馈网络 + 残差与归一化，多层堆叠；计算量随长度平方增长。
  • 时间序列的单个点语义弱 → 分块（PatchTST）：一段作为一个 token，既有语义又省计算。
  • 时序大模型在海量数据上预训练，可零样本预测，适合做强基线和冷启动。
  • 简单模型（DLinear、ETS、GBDT）常常很强——任何深度模型都要先和它们比。
