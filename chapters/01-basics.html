老板问"下个月要备多少货"，运维问"今晚流量会不会打爆机器"，运营问"日活掉了 5% 算不算异常"——这些都是时间序列问题。这一章先建立直觉：时间序列是什么、里面藏着哪几种规律、一个预测任务要先想清楚哪几件事。

什么是时间序列

时间序列就是按时间先后排列的一串观测值：每天的销量、每小时的用电负荷、每分钟的接口响应时间。它和普通表格数据最大的区别只有一条——顺序本身就是信息。

一张用户表，把行打乱没有任何损失；一条销量曲线，把日期打乱就什么都没了。因为今天的值和昨天、上周同一天的值是相关的，这种"自己和过去的自己相关"叫自相关，是所有时序模型赖以预测的根本。

🧪 实验：把时间顺序打乱，会丢掉什么？

点"打乱顺序"：均值、标准差一点没变（它们不关心顺序），但"相邻两天的相关性"直接掉到 0 附近。平均数这类统计量看不见的东西，正是时间序列分析要研究的东西。

销量曲线：供应链要未来 2–4 周的日预测来补货；财务要未来 12 个月的月预测来做预算；运营要知道大促当天比"没有大促会怎样"多卖了多少。问题不同，预测的粒度、步长、评估标准全都不同——所以动手建模前，先把业务问题问清楚。

四种成分：趋势、季节、周期、噪声

看似杂乱的曲线，通常可以拆成几种简单规律的叠加：

成分含义业务例子
趋势 $T_t$长期的上升或下降用户规模增长带来的销量上行；老产品逐年萎缩
季节 $S_t$固定周期的重复波动周末销量高、夏季用电高、午晚高峰
周期 $C_t$不固定长度的起伏经济景气循环、行业库存周期（通常并入趋势一起处理）
噪声 $R_t$剩下的随机波动天气、偶然事件、测量误差——不可预测的部分

此外业务数据里还有两类"不速之客"：事件（大促、节假日、发版——已知原因、可提前安排）和异常（系统故障、刷单——需要清洗）。第 03 章专门讲怎么区分和处理它们。

加法模型 vs 乘法模型

成分的组合方式有两种：

$$\text{加法：}\; y_t = T_t + S_t + R_t \qquad\qquad \text{乘法：}\; y_t = T_t \times S_t \times R_t$$

判断方法很直观：季节波动的幅度是否随着水平变大而变大。周末总比平时多卖 200 件（固定差值）是加法；周末总比平时多卖 20%（固定比例）是乘法。业务量在增长的数据，绝大多数是乘法。

🧪 实验：序列合成器——亲手造一条时间序列
合成结果（蓝）与其中的趋势（橙）
季节成分与噪声成分

试一试：① 把趋势调大再切到"乘法"，观察季节波动如何越来越大（像喇叭口）；② 把噪声拉到最大，规律被淹没——这就是"信噪比低"的数据，任何模型都难预测；③ 把季节幅度调到 0，只剩趋势 + 噪声。

💡 乘法变加法的小技巧

对乘法模型两边取对数：$\log y_t = \log T_t + \log S_t + \log R_t$，就变成了加法。这就是为什么后面很多模型在建模前会先对数据取 $\log$——喇叭口被"压平"了，模型更好学。

粒度与重采样

粒度（频率）是相邻两个观测的时间间隔：小时、日、周、月。同一份数据在不同粒度下看到的规律不同，把细粒度聚合成粗粒度叫重采样。

🧪 实验：同一份销量，按日 / 周 / 月看

日粒度能看到周内节奏和大促尖峰；聚合到周，周内节奏消失、曲线变平滑；聚合到月，只剩趋势和年度季节。先别勾选"去掉不完整周期"，看看月度曲线的最后一个点——如果数据只到月中，这个点会假装"暴跌"。这是报表里最常见的误读之一。

⚠️ 粒度怎么选
  • 跟着决策走：按周下采购单，就预测到周；没必要预测到小时再加总。
  • 越粗越稳、越细越噪：聚合会抵消噪声，粗粒度预测通常相对误差更小。
  • 聚合前先确认口径：销量可以求和，价格、库存、日活不能直接求和（要用均值或期末值）。

定义一个预测任务

"预测销量"不是一个完整的任务描述。下图是每个预测任务都要回答的几件事：

要回答的问题选项为什么重要
预测什么、什么粒度销量 / 销售额；SKU-门店-日 / 品类-周粒度越细，序列越多、越稀疏、越难
预测多远（步长 $h$）单步（明天）/ 多步（未来 28 天）越远越不准；多步预测有专门的策略（第 08 章）
要一个数还是一个范围点预测 / 区间预测 / 分位数备货要的是"有 95% 把握够卖的量"，不是平均值（第 05 章）
有没有外部信息只用自身历史（单变量）/ 加协变量促销计划、节假日、天气往往比模型选择更重要
协变量未来是否已知已知未来（日历、促销计划）/ 未知未来（实际天气、竞品动作）未来不知道的变量，预测时不能直接用
预测错了的代价缺货 vs 积压；误报 vs 漏报决定用什么评估指标、往哪个方向偏更安全

时间序列分析不只有预测。同一套工具还用来做异常检测（今天的值正常吗）、归因分析（这次下跌是趋势变了还是季节波动）和效果评估（活动带来了多少增量）——它们都建立在"先预测出正常情况下应该是多少"的基础上。

Python 里怎么起步

pandas 对时间序列有一等公民级别的支持。把时间列设成索引之后，重采样、滚动窗口、按日期切片都是一行代码。

Python 参考代码：读入、设索引、重采样、画图 
import pandas as pd
import matplotlib.pyplot as plt

df = pd.read_csv("sales.csv", parse_dates=["date"])
y = df.set_index("date")["sales"].sort_index()

y = y.asfreq("D")                 # 显式声明日频率：缺失的日期会变成 NaN（第 03 章处理）
print(y.index.min(), y.index.max(), y.isna().sum())

weekly = y.resample("W-MON", label="left", closed="left").sum()   # 周一为一周的开始
monthly = y.resample("MS").sum()                                    # 月初为标签
monthly = monthly.iloc[:-1]       # 最后一个月如果不完整，丢掉它

y["2024-10":"2024-12"].plot(figsize=(10, 3), title="最近三个月")
y.rolling(7).mean().plot()        # 7 日移动平均（第 02 章）
plt.show()

本章要点与小测验

  • 时间序列 = 按时间排列的观测，顺序就是信息；自相关是可预测性的来源。
  • 四种成分：趋势、季节（固定周期）、周期（不固定）、噪声；业务数据还要额外识别事件和异常。
  • 季节幅度随水平放大 → 乘法模型；取对数可以把乘法变加法。
  • 粒度跟着决策走；聚合时注意口径和不完整周期。
  • 建模前先定义清楚：预测什么、多细、多远、点还是区间、有什么协变量、错了的代价。
